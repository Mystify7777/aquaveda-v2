## 🔒 Locked — Learn Knowledge Taxonomy and Faceted Discovery (ADR-0011; recorded by #226)

**Status: accepted.** Full decision: `docs/adr/ADR-0011-learn-knowledge-taxonomy-and-faceted-discovery.md`. Knowledge lifecycle and approved-only public visibility remain unchanged.

- **LRN-L1 — Cardinality.** One primary Category per article; zero or more Topic tags; one Region string per article in v1.
- **LRN-L2 — Controlled identity.** Stable immutable slugs and display names. Active terms may be assigned/filtered; retired terms remain renderable on existing articles but cannot be newly assigned, filtered, or used for related scoring.
- **LRN-L3 — Rename vs merge.** Display-name rename preserves identity. Semantic merge requires migration to a canonical slug; retired old slugs remain recognized for rendering.
- **LRN-L4 — Governance.** Source-controlled vocabulary. Additions/renames/merges/retirement require reviewed PRs and tests; persisted-reference rewrites require idempotent migration. No runtime editor in v1.
- **LRN-L5 — Region normalization.** Preserve original display values. API and migration code must call one shared server-side utility with the exact sequence: ECMAScript NFKC; collapse Unicode White_Space runs to ASCII space; trim; ECMAScript default `toLowerCase()`; then explicit alias lookup. This is not full Unicode Default Case Folding; no locale-sensitive casing or independent reimplementation. Shared test vectors include ASCII case/whitespace, NBSP, compatibility characters, accented Latin, Cyrillic, and `Straße → straße` (not `strasse`). `Bihar` and `Bihar, India` remain distinct absent an explicit reviewed alias. Blank is unclassified; unresolved legacy values are reported; no multi-region support.
- **LRN-L6 — Region facet options.** Derive only from approved articles with non-empty normalized keys; one option per canonical key. Preserve each article's source display string. Prefer an explicit alias canonical label; otherwise select the lexicographically smallest NFKC + whitespace-normalized original display variant using Unicode code-point order, with original UTF-8 byte sequence as exact-tie breaker. Sort options by canonical key using code-point order. Database iteration order and locale collation must not affect labels.
- **LRN-L7 — Facet composition.** Category single-select. Multiple Topics OR; multiple Regions OR. Category, Topic facet, Region facet, and title/body search combine with AND. Invalid/retired Category/Topic filters fail validation; unknown Region keys validly return no matches.
- **LRN-L8 — Public visibility.** Every public Learn query retains mandatory `status=approved`.
- **LRN-L9 — Search contract.** Search matches title OR body case-insensitively and never relaxes approved-only visibility. #232 must document its concrete MongoDB strategy, matching/token semantics, indexes/trade-offs, executionStats or equivalent query-plan evidence (selective and broad queries), measured latency on a representative fixture/staging dataset, scale boundary/revisit trigger, and confirmation that no unbounded case-insensitive body-regex scan was introduced without measurement and justification.
- **LRN-L10 — URL/UX.** URL-addressable state; desktop sidebar, mobile drawer/sheet; active chips, clear-all, counts, search, pagination.
- **LRN-L11 — Related Knowledge.** Candidates approved-only, exclude source, and must have at least one active Category/Topic identity. This eligibility requirement applies even when Region is the sole matching signal: such a candidate may qualify at +1 only if it has an active taxonomy identity. Score: same active Category +4; each shared active Topic +2 (max +6); same normalized Region +1. Retired terms do not contribute. Sort score DESC, `updatedAt DESC`, `_id ASC`; bounded result count.
- **LRN-L12 — V1 exclusions.** No taxonomy collection, arbitrary user tags, AI tagging/ranking, followable topics, full Unicode case-folding library, or runtime editor.
- **LRN-L13 — Existing governance.** Lifecycle, review authority, author/reviewer rules, anonymous read boundary, and approved-only visibility remain unchanged.

Implementation contracts are tracked in #228–#240. See ADR-0011 for the exact algorithm, test vectors, Region facet label selection, search verification requirements, and candidate eligibility details.
